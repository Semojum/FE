## 1. 앱 이름 및 로고 변경

앱 이름 `BrailleMate` → `세모점`, 앱 아이콘을 세모점 심볼로 교체.

- `src-tauri/tauri.conf.json` — 창 `title` → `세모점`, `productName` → **`Semojum`(ASCII)**.

> ⚠️ **`productName`에 한글을 쓰면 Windows 빌드가 깨진다.** 처음에는 `productName`도
> `세모점`으로 뒀는데 v3.0.2 태그 빌드가 MSI 단계에서 실패했다 —
> NSIS(`세모점_3.0.2_x64-setup.exe`)는 통과했지만 WiX 3의 `light.exe`가
> `세모점_3.0.2_x64_en-US.msi`를 만들지 못했다. en-US 컬처(코드페이지 1252) MSI에
> 한글 ProductName이 들어가지 않는다(`candle`은 통과, MSI를 실제로 쓰는 `light`에서 실패).
> 그래서 사용자에게 보이는 창 제목·화면은 세모점으로 두고, 번들 식별용 `productName`만
> ASCII로 되돌렸다. Windows 프로그램 목록에는 `Semojum`으로 보인다.
> 한글 이름을 프로그램 목록에까지 반영하려면 MSI를 빼고 NSIS만 내거나
> (`bundle.targets: ["nsis"]`), `bundle.windows.wix.language`를 `ko-KR`로 두고 검증해야 한다.
- `src-tauri/icons/*` — `bunx tauri icon public/semojum-symbol.png`로 전부 재생성.
- `index.html` `<title>`, `src/utils/outputWindow.ts`(결과 창 제목), `package.json` name,
  `.github/workflows/build.yml`(릴리스 이름·artifact 이름).
- 헤더 로고 참조를 `BrailleMate_Logo.png` → `semojum-wordmark.png`로 정리.
  (두 파일은 바이트가 같은 세모점 워드마크다 — 그림은 이미 바뀌어 있었고 파일명만 옛것이었다.)

> ⚠️ `identifier`(`com.braillemate.app`)는 그대로 두었다. 바꾸면 기존 설치본과
> 다른 앱이 되어 자동 업데이트로 덮어쓰이지 않는다.
> `productName`이 바뀌었으므로 다음 릴리스의 설치 파일 이름이 `세모점_x.y.z_x64-setup.exe`가
> 된다. 업데이터는 `latest.json`의 URL을 따라가므로 동작에는 영향이 없지만, 릴리스
> 산출물 이름이 바뀌는 것은 확인하고 태그를 밀 것.

## 2. 앱 종료 안됨

**원인.** `onAppClose`가 창 닫기를 `preventDefault()`로 붙잡고 저장을 끝낸 뒤
`appWindow.destroy()`를 부르는데, `destroy`가 capability에 없었다.
`core:window:default`에는 `destroy`가 들어 있지 않고 `allow-close`만 명시돼 있었으므로
호출이 거부되고, 닫기는 이미 취소된 뒤라 창이 영영 닫히지 않았다.

**수정.**

- `src-tauri/capabilities/default.json` — `core:window:allow-destroy` 추가.
- `src/utils/appLifecycle.ts` — ① 결과 전용 창(반으로 나누기)이 열려 있으면 먼저
  정리한다(메인만 없애면 프로세스가 남는다) ② `destroy`가 실패하면
  `plugin-process`의 `exit(0)`으로 확실히 끝낸다.

## 3. mode a 우측에서 영어는 되는데 한글 입력 안됨

**원인.** 격자의 실제 입력을 받는 숨은 `<input>`이 `value=''` + `onChange` noop인
**제어 컴포넌트**였다. 영문은 `keydown`에서 `preventDefault` 후 직접 칸에 넣으므로
input을 거치지 않아 멀쩡했지만, 한글은 IME 조합 문자열이 input에 쌓여야 하는데
React가 렌더마다 값을 `''`로 되돌려 조합이 끊겼다.
(2026-08-09 "초안 수정 시 내용 입력 안 됨"이 재현되지 않았던 이유 — 그때 e2e는 영문을 쳤다.)

**수정.** `src/component/features/conversion/BrailleGrid.tsx` — 숨은 input을 비제어로
바꾸고(`defaultValue`), 조합이 끝나면 `compositionend`가 값을 칸에 넣고 input을 비운다.
조합을 거치지 않는 입력(붙여넣기 등)은 새 `onInput` 경로가 받는다.
브라우저마다 마지막 `input`과 `compositionend`의 순서가 달라 양쪽으로 막았다.

**테스트.** `BrailleGrid.test.tsx` — 조합 확정 시 `onEditRow`가 한 번 불리고 input이 비워진다.

## 4. 파일 업로드 시 "결과가 없습니다"가 떴다가 변환 완료돼야 결과가 뜸

**원인.** 결과 패널 분기가 `isUploading` → `isStreaming && 결과 없음` → … 순인데,
업로드 응답을 받은 뒤 SSE가 붙기까지 **둘 다 false인 구간**이 있다.
그 사이 마지막 분기인 "결과가 없습니다."로 떨어졌다.

**수정.** `src/App.tsx` — `isConverting`(업로드 중 · 스트리밍 중 · jobId가 있는데 아직
변환이 안 끝남)을 만들어 그 구간도 "분석 중..."으로 덮는다.

## 5. mode A 좌측 원본 잘려서 보임

**원인.** `FilePreviewer`가 PDF를 `width={500}` 고정으로 그렸다. 패널이 그보다 좁으면
`justify-center`로 가운데 정렬된 페이지의 **좌우가 똑같이 잘려** 문제 번호가 사라졌다.

**수정.** 뷰포트 폭을 `ResizeObserver`로 재서 페이지 폭을 패널에 맞춘다.
패널이 넓으면 그만큼 크게 그리므로 여백도 줄어든다.

## 6. 화면 크기 조정

가로 스크롤 없이 32칸이 들어가려면 결과 패널 안쪽 폭이 약 660px 필요한데,
기존 배치(`max-w-7xl` · `px-6` · `p-8` · `gap-8` · `flex-[1.4]`)로는 1280px 창에서 620px대였다.

**수정.**

- 컨테이너 `max-w-7xl` → `max-w-[1560px]`, 좌우 패딩 `px-6` → `px-4`, 패널 간격 `gap-8` → `gap-6`,
  패널 내부 `p-8` → `p-6`, 결과 패널 비중 `flex-[1.4]` → `flex-[1.5]`, 격자 `px-3` → `px-2`.
- 헤더 로고 줄의 `-ml-15`(왼쪽으로 60px 밀어내던 값) 제거.
- 기본 창 크기 `1280×800` → `1440×900`, 최소 `800×600` → `1024×640`.

기본 창(1440)에서 결과 패널 안쪽 폭이 ~770px가 되어 확대 없이 32칸이 들어간다.
최소 창(1024)에서는 여전히 가로 스크롤이 남는다.

## 7. mode a 우측 점자 태깅 회색 처리

본문 `contents`에 `<!점역자주>…<!/점역자주>` 래퍼가 그대로 실려 온다.
FE가 벗기면 다운로드 파일과 어긋나므로(BE·AI 몫) **지우지 않고 흐리게만** 그린다.

`BrailleGrid`가 본문 행을 순서대로 이어 읽으며 태그가 차지하는 칸을 표시하고,
그 칸만 회색(`#c8ccd4`)으로 렌더한다. 태그가 32칸 경계에서 접혀 다음 행으로 넘어가도 이어서 잡는다.

## 8. 마이페이지 모드 A·C 원본 PDF 렌더링 안됨

BE는 2026-08-09에 S3 CORS 추가·presigned 전환·공개 읽기 회수까지 마쳤다.
**FE에 남아 있던 원인 1건을 실서버로 확인했다.**

- `original.url` 호스트는 `semojum-bucket.s3.ap-northeast-2.amazonaws.com`인데,
  Tauri http capability 허용 목록은 `api.semojum.app`·`storage.googleapis.com`뿐이었다.
  데스크톱은 `httpFetch`가 `tauri-plugin-http`를 타므로 이 목록에 없는 호스트는 **플러그인 단에서 거부**된다.
  → 브라우저(`bun run dev`, vite proxy)에서는 되고 데스크톱 앱에서만 빈 패널이 되는 상태였다.

**수정.** `src-tauri/capabilities/default.json`에
`https://*.s3.ap-northeast-2.amazonaws.com/*` 추가.

**실서버 확인 (2026-08-12, 계정 `org0102`).**
1페이지 PDF를 mode a로 올려 `GET /api/users/jobs/{id}/pages/1` → `original.url` 수신,
그 URL을 직접 받아 `200 application/pdf` 확인. 검증에 만든 작업은 휴지통 → 완전 삭제로 원복했다.

> 데스크톱 실기 확인은 아직이다. Windows 빌드에서 마이페이지 → 모드 A·C 파일 클릭 →
> 원본 렌더링을 한 번 봐 주면 좋겠다.

## 9. 다른 페이지 시각자료 데이터가 표기되는 문제 — **미해결**

재현 자료가 없어 원인을 특정하지 못했다. 확인한 것과 남은 것:

- 페이지별 매핑(`usePageStreamHandler` → `mapPageResult`)은 `page_done.page_no` 기준으로만
  상태에 넣는다. 페이지를 섞을 경로가 없다.
- 요소 id가 페이지마다 재사용되면 페이지 간 오염이 가능해 실서버로 확인했다 —
  **UUID라 전역 고유**다. 이 경로는 아니었다.
- 다만 대체 초안 피커가 블록 id만 들고 `blocksByPage` 전체를 훑어 **먼저 걸린 페이지**의
  블록을 열고 있었다. 지금 구조에서는 드러나지 않지만 옳지 않아 페이지까지 지정하도록 고쳤다
  (`draftTarget = {pageNo, blockId}`).

**필요한 것.** 문제가 난 원본 파일과 jobId, 그리고 "어느 페이지에서 어느 페이지 자료가 보였는지".
AI·BE 응답(`page_done`)에 다른 페이지 내용이 실려 오는지부터 갈라야 한다.

## 10. AI 생성 블록 표기 방식 변경

**전제부터 어긋나 있었다.** 리뷰어는 주황색을 "AI 생성 블록" 표시로 읽었지만,
디자인 `V3/BlockCard`의 상태는 `default`(회색 테두리) · `selected`(주황 `#f47726` 테두리) ·
`review`(주황 테두리 + 크림 배경) 3종이고, **주황은 "선택된 블록(원본 대조)"**이다.
AI 생성 여부를 나타내는 상태는 디자인에 없다.

요청대로 선택 강조를 배경색으로 바꾸되, 이미 배경색을 쓰던 `review`와 섞이지 않게 갈랐다.

| 상태 | 디자인 | 반영 |
| --- | --- | --- |
| selected (원본 대조) | 주황 테두리 | **연한 주황 배경 `#fbe4d3`** (테두리 없음) |
| review (검토 필요 · `is_blocked`) | 주황 테두리 + 크림 배경 | 크림 배경 `#fdf8e3` + **주황 테두리** (디자인대로) |

`review`는 코드에 배경(`amber-50`)만 있고 테두리가 없었다 — 이번에 디자인에 맞춰 테두리를 넣었고,
그 덕에 두 상태가 테두리 유무로도 갈린다.

## 11·12. 블록 버튼 · 대체 텍스트 버튼

우클릭 메뉴에만 있던 기능을 결과 패널 상단 툴바로 꺼냈다.
대상은 커서가 놓인 줄의 블록이며, 우클릭 메뉴는 그대로 둔다.

- 왼쪽: `블록 추가` · `위로` · `아래로` · `블록 삭제`
- 오른쪽: `대체 텍스트` — 대체 초안이 있는 블록에서만 활성(없으면 이유를 툴팁으로).
  이름은 디자인 모달 제목(`대체 텍스트 선택`)을 따랐다.

> 디자인에는 `V3-03 블록 편집 — hover 액션`으로 **블록 오른쪽 끝에 뜨는 `↑ ↓ 🗑`**가
> 정의돼 있다(리뷰어의 "우측에 버튼으로"와도 맞는다). 다만 지금 결과 패널은 블록 카드가
> 아니라 26줄×32칸 판면 격자라 블록이 여러 행에 걸쳐 있어, 항상 보이는 상단 툴바로 가기로
> 했다(2026-08-12 결정). hover 액션이 필요해지면 블록의 행 범위에 맞춰 띄우면 된다.

## 14. 다운로드 시 저장 폴더 선택

`saveBlob`이 anchor + blob URL로 webview 기본 다운로드 폴더에 말없이 떨어뜨리던 것을,
데스크톱에서는 **저장 대화상자**로 위치·이름을 고르게 바꿨다. 저장 후 경로를 토스트로 알린다.
브라우저(개발용)에서는 종전 방식 그대로.

- 추가: `@tauri-apps/plugin-dialog`, `@tauri-apps/plugin-fs` (JS·Rust 양쪽), `src-tauri/src/lib.rs` 등록,
  capability `dialog:allow-save` · `fs:allow-write-file`.
  fs 쓰기 범위는 대화상자로 고른 경로에만 열린다.

## 15. 로그인 화면 정보 변경

`© 2024 BrailleTech · 이용 약관 · 개인정보 처리방침 · 고객지원 · Service Status` 줄은 모두 사라졌다.

## 추가 제보: "앱이 강제로 꺼진다" — 자동 업데이트가 원인

Review DB에 없던 제보. 현장에서는 **작업 관리자에 웹뷰가 여러 개 보여서** 그런 것 같다고
보고됐지만, 웹뷰 개수는 원인이 아니다.

### 원인

`tauri-plugin-updater`의 **Windows 설치 경로는 앱을 죽인다.**
설치 파일을 `ShellExecuteW`로 띄운 다음 곧바로 `std::process::exit(0)`을 호출한다.

```
// tauri-plugin-updater 2.10.1 · src/updater.rs
#[cfg(windows)] impl Update {
    fn install_inner(&self, bytes: &[u8]) -> Result<()> {
        …
        unsafe { ShellExecuteW(…) };
        std::process::exit(0);      // ← 여기
    }
}
```

그런데 `useAppVersion`이 **앱을 켤 때마다** `checkForUpdates()`를 `autoInstall: true`(당시 기본값)로
불렀다. 로그인 화면에서 이미 돈다. 그래서 새 릴리스가 올라와 있으면:

1. 사용자가 앱을 켠다
2. 백그라운드로 새 버전을 내려받아 **자동으로 설치를 시작**한다
3. 플러그인이 `exit(0)` — **앱이 예고 없이 사라진다**

`close-requested`를 거치지 않으므로 종료 시 저장 플러시(`saveAllDirty`)도 실행되지 않는다.
**단순한 놀람이 아니라 미저장 편집이 사라지는 데이터 유실이다.**

타이밍도 맞는다 — `v3.0.1`은 2026-08-10 발행이고 그 전 버전은 `v3.0.0`이다.
8/10 이후 3.0.0을 쓰던 사용자는 앱을 켤 때마다 이 경로를 탔다.
(지금 설치본 3.0.1 == `latest.json` 3.0.1이라 오늘 새로 켜면 재현되지 않는다.
 **3.0.0 설치본으로 켜야 재현된다.**)

MSI 경로(현 `latest.json`이 가리키는 산출물)는 `msiexec`에 권한 상승이 필요해,
사용자가 UAC를 취소하면 **앱만 죽고 설치도 안 된 채 끝난다** — 가장 나쁜 형태다.

### 수정 — 디자인 `V3-05`가 원래 맞았다

디자인은 토스트에 **[지금 설치] · 나중에**, 강제 업데이트에 **[지금 업데이트]**를 두고
"지금 설치하면 약 10초 후 자동으로 다시 시작됩니다"라고 알린다. 즉 **설치는 사용자가 고른
시점에만** 일어나야 한다. 코드가 그 반대로 되어 있었다.

- `src/utils/updater.ts` — `autoInstall` 기본값을 **`true` → `false`**로. Windows 종료 동작을 주석에 명시.
- `src/hooks/UseAppVersion.ts` — 시작 시에는 **확인만**(`autoInstall: false`).
  `installNow()`를 새로 두고, 설치 전에 `onBeforeInstall`(= `editor.saveAllDirty`)로 저장을 밀어낸다.
  저장이 실패해도 설치는 막지 않는다(강제 업데이트를 잠그면 안 된다).
- `src/component/features/update/UpdateGate.tsx` — 문구·버튼을 디자인대로.
  `다시 시작` → `지금 설치`, `업데이트하고 다시 시작` → `지금 업데이트`,
  "설치가 시작되면 앱이 잠시 종료됐다가 다시 시작됩니다" 안내 추가.
- `src/App.tsx` — 배선.

**테스트.** `src/hooks/__tests__/UseAppVersion.test.tsx` 4건 — 시작 시 `autoInstall: false`로만
부르는지, `installNow`가 저장 → 설치 순서인지, 저장 실패해도 설치가 진행되는지,
결과 전용 창에서는 확인조차 하지 않는지.

### 웹뷰가 여러 개인 것은 정상이다

- Windows의 WebView2는 앱 하나당 `msedgewebview2.exe`를 **여러 개**(브라우저·GPU·렌더러·유틸리티·
  크래시패드) 띄운다. WebView2를 쓰는 모든 앱이 그렇고, 강제 종료와 무관하다.
- 이 앱은 여기에 더해 **반으로 나누기**를 쓸 때만 두 번째 웹뷰 창(`output`)을 만든다.
  창을 만드는 곳은 `src/utils/outputWindow.ts` 한 곳뿐이고, 만들기 전에 같은 라벨의 창을
  닫으므로 계속 쌓이지 않는다.
