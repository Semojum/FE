# 사용 설명서 원본

`docs/세모점_사용설명서.pdf`를 만드는 원본이다. 3.2.5까지는 PDF만 있고 원본이 없어
고칠 때마다 통째로 다시 만들어야 했다 — 이제 이 폴더가 단일 출처다.

```
index.html      본문
manual.css      인쇄용 스타일 (A4)
figures/        화면 사진
build.sh        index.html → ../세모점_사용설명서.pdf
```

## 다시 만들기

```sh
bash docs/manual/build.sh
```

헤드리스 크롬의 print-to-pdf로 뽑는다. 목차 쪽 번호는 한 번 뽑아 각 장이 앉은 쪽을
읽어 채워 넣고 다시 뽑는다(2패스) — `index.html`의 장 머리에 있는 `CHAPMARK<n>END`가
그 표식이고, 눈에는 보이지 않는다. 크롬 경로가 다르면 `CHROME=... bash build.sh`.

## 버전을 올릴 때

세 자리를 함께 고친다 — 표지, 제 15 장 제품 사양, 발행일.

## 화면 사진

`figures/`는 2026-09-02에 dev 서버(`bun dev`)를 크롬으로 띄워 CDP로 찍었다.
찍을 때 두 가지를 임시로 손봤다 — 다시 찍을 때도 그래야 한다.

1. `utils/devMode.ts`의 `getBuildChannel`이 브라우저를 늘 `development`로 보므로,
   `production`을 돌려주게 임시로 바꾼다. 안 그러면 "v3.2.5 개발" 배지가 찍히고
   준비 중 기능이 풀린 채로, 다운로드 창에는 개발 전용 단추가 섞여 나온다.
2. 화면은 1440×720 CSS 픽셀 · deviceScaleFactor 2로 찍어 2880×1440을 얻고,
   `sips -Z 1600`으로 줄여 JPEG(품질 80)로 넣는다.

사진 속 왼쪽 아래 버전 배지는 찍은 시점의 버전이다 — 표지·제 15 장의 버전과
한 판 차이가 날 수 있다. 화면을 다시 찍을 때 저절로 맞는다.

**번호 표식은 사진에 굽지 않는다.** `index.html`에서 `.shot`/`.cal`로 얹으므로,
화면을 다시 찍어도 좌표(%)만 고치면 되고 표와 어긋났을 때 고칠 자리도 한 곳뿐이다.

옛 사진 그대로인 것 둘:

| 파일 | 왜 |

| `latex.jpg` | 라텍스 변환기 화면이 그대로다 |
