A화면과 파일이 어긋나는 것 — 최우선

A-1조판 옵션에 showChangeLine 추가BE신규

  • 증상원본 페이지 번호는 켜 둔 채 변경선만 끄면 화면에서는 줄이 사라지는데 내려받은 .brf에는 그대로 들어갑니다. 작업을 다시 열면 변경선이 켜진 채로 돌아옵니다.
  • 확인한 것명세의 조판 옵션(V30) 열한 항목에 변경선 스위치가 없습니다 — cellsPerLine · linesPerPage · pageNumberLine · coverPages · sourcePageStart · braillePageStart · showSourcePageNumber · showBraillePageNumber · footerAlign · editScope · advancedAi.
  • 지금 서버가 하는 것showSourcePageNumber=false이면 변경선도 함께 꺼지는 결합 동작뿐입니다(2026-09-02). 다운로드 명세도 “페이지행 생략 — 변경선은 유지”라고 적고 있습니다.
  • 필요업로드 폼과 layout_options에 showChangeLine(Boolean, 기본 true)을 더하고, braille-assist의 show_change_line으로 넘겨 주십시오. 라이브러리 쪽은 이미 받습니다.
  • 규칙showSourcePageNumber=false면 이 값과 무관하게 꺼집니다(라이브러리가 그렇게 처리).
  • FE 현황FE가 이미 이 필드를 보내고 응답에서 읽습니다 — 지금은 모르는 필드라 무시될 뿐이라, 서버가 받기 시작하면 FE는 고칠 것이 없습니다. 저장·복원도 그때 함께 됩니다.
  • 검증번호는 켜고 변경선만 끈 작업을 내려받아 ⠤… 줄이 없는지.

S-4점역된 꼬리말을 페이지 조회 응답에BE

  • 증상판면 페이지행의 꼬리말 자리가 화면에서 늘 빈칸입니다.
  • 범위명세상 파일에는 들어갑니다 — 다운로드 명세: “다운로드 시점에 AI TranslateText로 점역 → 페이지행 가운데 배치”. 즉 화면 미리보기만의 공백입니다.
  • 원인SSE·페이지 조회 응답 어디에도 점역된 꼬리말 필드가 없습니다. 오가는 것은 footerText(묵자)뿐이고, FE에는 점역기가 없습니다.
  • 필요페이지 조회 · SSE 응답에 점역된 꼬리말 필드 하나. 구간마다 다르면 {점자면번호: 꼬리말} 형태(라이브러리가 이미 이 형태를 받습니다).
  • 파급이것이 막혀 꼬리말 정렬 · 수정 적용범위를 화면에서 QA할 수 없습니다.
확인 요청 — 파일에서도 비어 있었습니까? QA에서 “꼬리말이 아예 점역이 안 되고 빈칸”이라는 보고가 있었습니다. 화면이면 위 S-4(알려진 공백)이고, 내려받은 .brf라면 명세와 어긋나는 BE 버그라 성격이 완전히 다릅니다. 어느 쪽인지 확인 부탁드립니다.

B텍스트 점자 번역의 원본 페이지

B-1텍스트 점자 번역의 30줄 청크 — 설계 재검토BE신규

  • 확인한 것버그가 아니라 명세된 동작이었습니다. Job 생성 명세의 모드별 페이지 분리 표에 b | TXT = 30줄 청크라고 적혀 있습니다(a·c는 PDF 페이지).
  • 그래서 생기는 일“원본 페이지”가 원문의 쪽과 아무 관계가 없습니다. 페이지행의 원본 쪽 번호는 30줄마다 1씩 오르는 숫자이고, 원본 페이지 변경선도 30줄마다 한 번씩만 들어갑니다.
  • 현장에서 본 증상“원본 쪽 번호가 사실상 누락된다”, “변경선이 초안 생성에서는 다 보이는데 텍스트 점자 번역에서는 일부만 보인다” — 둘 다 이 한 가지에서 나옵니다.
  • 결정 필요셋 중 하나를 정해 주십시오.
    • ① 출처의 쪽 구조를 보존 — FE가 HWP·HWPX를 텍스트로 바꿔 올리므로, 쪽 경계를 표식으로 실어 보내는 약속을 두면 서버가 그대로 나눌 수 있습니다(FE 작업 필요).
    • ② 청크 크기를 조판 옵션으로 — 30줄 고정 대신 값을 받습니다. 여전히 원문 쪽과는 무관합니다.
    • ③ 이 모드에서는 원본 쪽 번호·변경선을 감춘다 — 뜻이 없는 숫자를 안 보여 주는 쪽. FE만으로 가능하며 반나절이면 됩니다.
  • FE 의견③으로 먼저 막고, 필요가 확인되면 ①을 하는 것을 권합니다 — 지금은 잘못된 숫자가 점역사에게 그대로 보입니다.

C표식이 파일에 실리지 않는 것

L-2쪽바꿈 표식을 .brf에 반영braille-assistBE

  • 증상판면에서는 면이 갈리지만, 서버가 만든 파일에는 <!쪽바꿈>이 점자 글자로 찍히고 면은 갈리지 않습니다.
  • 기능커서 자리부터 새 점자 페이지 첫 줄에서 시작하게 하는 것(Ctrl+Enter). 단원이 바뀌는 자리에서 씁니다. 초안 생성에는 필요 없고 점자 판면을 만드는 두 모드에만 있습니다.
  • 필요조립 단계에서 표식을 만나면 그 자리에서 면을 가르고 표식은 버립니다.
  • 현황FE는 결과물이 깨지지 않도록 이 기능을 막아 둔 상태입니다.

L-3구간 꼬리말 표식을 .brf에 반영braille-assistBE

  • 증상같은 문제, 같은 문법(<!꼬리말:…>).
  • 필요L-2와 한 묶음으로 처리하는 것이 맞습니다. 라이브러리에는 이미 buildPages(..., footers) 자리가 있어 표식 해석만 붙이면 됩니다.
주의 — 라이브러리는 세 구현을 함께 고쳐야 합니다 braille-assist는 python · ts · java 세 구현과 vectors.json이 같은 출력을 내야 합니다. L-2 · L-3은 한 PR로 묶어 주십시오.
