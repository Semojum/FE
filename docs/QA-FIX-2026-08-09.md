## 1. 수정 + 화면 확인 완료

### 1-1. 모드 이름이 업데이트되지 않음 (QA #3)

**원인.** 탭 이름이 화면 라벨이자 내부 식별자였다. `TABS.OCR === 'OCR 변환'` 값 자체를 탭 스냅샷 키로 쓰고 `activeTab === TABS.OCR`로 모드를 판정해, 라벨만 바꾸면 모드 분기가 전부 깨졌다. 마이페이지는 이미 새 이름을 쓰고 있어 **같은 작업이 화면마다 다른 이름**으로 보였다.

**수정.** 식별자를 서버 mode와 같은 `'a' | 'b' | 'c'`로 바꾸고 라벨을 `TAB_LABEL`로 분리. 에러 문구도 라벨을 쓴다.

- `src/types/index.ts` · `src/utils/fileValidation.ts` · `src/App.tsx`

**확인.** 탭이 `초안 생성 / 텍스트 점자 번역 / 이미지 점자 번역`으로 표시.

### 1-2. 점자 입력 중 간헐적 영문자 (QA #2)

**원인.** 점자 모드에서도 일반 문자 입력 경로가 열려 있었다. 6점 키로 잡아 두는 것은 `S D F J K L` 여섯 개뿐이라, 퍼킨스 타법에서 흔한 `A · G · H · ;` 오타가 그대로 칸에 찍혔다. 한글 IME가 켜져 있으면 `preventDefault`가 IME 조합을 막지 못해 `compositionend`로 한글까지 추가 삽입될 수 있었다.

**수정.** 점자 모드에서는 점형·이동·삭제 키와 빈 칸(스페이스)만 받고, IME 조합 결과는 버린다.

- `src/component/features/conversion/BrailleGrid.tsx`

**확인.** 점자 격자에서 `a g h` 입력 → 격자 변화 없음.

### 1-3. 블록 박스가 32칸까지 가지 않고 끊김 (QA #11)

**원인.** 격자 한 행이 내용 폭이 아니라 **패널 폭**에 맞춰졌다. 행은 flex 컨테이너인데 칸은 `shrink-0`이라 오른쪽으로 넘치고, 강조 테두리는 넘친 칸이 아니라 행 박스 끝에 그려졌다. 첨부 스크린샷 실측 박스 폭 **598.5 CSS px** vs 필요 폭 26 + 32×19 + 4 ≈ **656 px** — 차이가 딱 한 칸 반이라 31칸 언저리에서 잘렸다. 래퍼가 `overflow-hidden`이라 가로 스크롤도 없었다.

**수정.** 면·행·격자 컨테이너에 `w-max`, 스크롤러를 `overflow-auto`로.

**확인.** 32칸 눈금까지 가로 스크롤되고, 9줄짜리 블록에서도 박스가 32칸 끝에서 닫힘.

### 1-4. 블록 추가·삭제가 안 됨 (QA #9)

**원인.** 격자 컴포넌트 자체는 정상이었다(단독 테스트로 확인). 문제는 두 가지가 겹친 것 —
① 우클릭이 커서를 옮기며 숨은 입력창에 포커스를 주는데, 그 `focus()`가 화면 밖 요소를 보이게 하려고 **격자를 스크롤**시켰다.
② `ContextMenu`가 capture 단계로 모든 `scroll`에 닫히도록 구독하고 있어, 메뉴가 **뜨자마자 사라졌다.**

**수정.** `focus({ preventScroll: true })` + 메뉴가 열린 직후 400ms 동안은 스크롤을 무시.

- `BrailleGrid.tsx` · `src/component/shared/ContextMenu.tsx`

**확인.** 우클릭 메뉴가 뜬 뒤 유지됨.

### 1-5. 블록 이동 (QA #9)

**원인.** 구현이 없었다. `reorderBlocks`는 훅에만 있고 호출부가 없었다.

**수정.** 우클릭 메뉴에 `위로 이동 / 아래로 이동` 추가. 저장 API는 **배열 순서 = reading_order**라 서버 변경은 필요 없다. 팝업 동기화를 위해 `moveBlock` 액션 추가.

### 1-6. 대체 초안 기능 부재 (QA #10) — **원인 실측 확정**

**원인.** 실서버 `drafts`는 아래 형태로 온다.

```jsonc
"drafts": [
  { "label": "생략",       "text": "그림 생략",                  "contents": [] },
  { "label": "짧은 제목",  "text": "그림: 건국대학교 상징 문장…", "contents": [] },
  { "label": "개조식 설명", "text": "그림: …",                    "contents": [] },
  { "label": "줄글 설명",   "text": "그림: …",                    "contents": [] }
]
```

초안 본문이 `contents`가 아니라 **`text`에 들어 있고 `contents`는 항상 빈 배열**이다. FE는 `contents`만 본문으로 읽고 빈 것을 버려서(`filter(d => d.content.length > 0)`) **초안 4개가 전부 걸러졌고**, 그 결과 `hasDrafts`가 늘 false라 메뉴가 영구 비활성이었다. 진입점이 격자 우클릭 하나뿐이라 사용자에게는 "기능이 아예 없는" 것으로 보였다.

**수정.**
- `contents`가 비면 `text`(점역자주 래퍼 제거 후)를 본문으로 쓰는 폴백 — `src/utils/mapPageResult.ts`
- 초안이 있는 블록은 줄번호 옆에 주황 점 표시 — `BrailleGrid.tsx`

**확인.** IoT5 표지 그림 블록에 주황 점 표시 → 우클릭 `대체 초안` 활성 → 피커에 4개 초안이 라벨과 함께 표시(서버가 고른 `selected_idx: 2` 강조) → `짧은 제목` 선택 시 본문 교체 + 판면 재조판.

> ⚠️ `contents`가 비는 것이 명세대로인지 BE/AI 확인이 필요하다. FE 폴백은 방어이지 정답이 아니다.

### 1-7. 1페이지 변환 완료인데 '변환 중' (QA #1)

**원인.** 결과 패널이 "이 페이지가 끝났는가"가 아니라 `스트림 진행 중 && 현재 페이지 블록 0개`로 판단했다. 이미 받아 둔 `pageStatuses`를 보지 않아 ① 아직 안 온 페이지로 넘기면 끝난 페이지 결과까지 통째로 사라지고 ② 결과가 0블록으로 매핑되면 `job_done`까지 계속 '분석 중'이었다.

간헐성의 원인은 따로 있었다 — SSE 콜백이 `activeTab`을 클로저로 잡고 ref 갱신은 렌더 후 effect에서 일어나, **탭 전환 직후 도착한 프레임이 이전 모드 기준으로 매핑**됐다. 모드마다 읽는 필드가 달라(`text_list` ↔ `braille_text_list`) 그 페이지 블록이 비었다.

**수정.**
- 표시 조건을 `isStreaming && gridRows.length === 0`으로 (한 페이지라도 오면 격자를 보여준다)
- SSE 결과 해석 모드를 `activeTab`이 아니라 **그 Job이 만들어진 모드**로 고정 (`jobTab`)

- `src/App.tsx` · `src/hooks/UseJobUpload.ts`

**확인.** 27쪽 변환 중 **10/27 시점에 이미 결과 격자 표시**.

**원인.** '변환 취소' 버튼은 원래 없었다. 테스터가 누른 것은 원본 패널 우상단 `X`(작업 비우기)이고, 확인 없이 곧바로 `handleReset → clearWorkspace`를 호출해 `jobId`가 비면서 SSE 구독이 끊겼다. **서버 작업은 계속 돌아간다.**

- 격자 편집 경로는 컴포넌트 단독 테스트에서 정상(클릭 → 포커스 → `onEditRow`).

## 4. FE 원인이 아님이 확정된 항목

### 레이아웃 순서 이상 (QA #13)

IoT5 보고서 27쪽 전체의 페이지 조회 응답을 캡처해 확인했다.

- 모든 페이지 항목에 `order` 필드가 존재
- **배열이 이미 `order` 오름차순으로 정렬되어 옴** — 어긋나는 페이지 **0건**

FE는 배열 순서대로 그리므로 이는 곧 `order` 순서와 같다. FE에 정렬을 추가해도 결과가 달라지지 않는다. 다운로드 파일도 서버 reading_order 기준이므로, **AI가 매기는 `order` 값 자체**를 봐야 한다.
